# Agent 能力边界

语言：[English](CAPABILITY_BOUNDARIES.md) | 中文

本文为 [CAPABILITY_BOUNDARIES.md](CAPABILITY_BOUNDARIES.md) 的中文译文；如有差异，以英文版为准。

Agent 处理的是这次交给它的仓库里、能通过补丁修掉的安全问题。它不负责治理 Git 历史、外部系统状态，也不负责需要组织协调的安全运营动作。

## 系统审查范围

默认情况下，Agent 只处理仓库内能看见、能修改的问题：源码里的漏洞、仓库里的安全配置、以及可以通过仓库内控制修正的安全缺陷。

这意味着以下问题可以进入自动修复候选：

- 当前源码中的注入、授权、不安全的数据暴露、输入处理等应用层漏洞。
- 当前仓库文件中的安全相关配置缺陷，例如 Dockerfile 默认 root 用户、不安全的框架默认配置、缺失的安全 header 配置。
- 当前源码中仍存在的硬编码密钥、凭据样例或危险默认值。
- 可以通过当前文件补丁阻止未来继续发生的泄露或误配置。

以下问题不属于 Agent 可完整处理的范围，最多作为后续人工处理、剩余风险或超出自动处理范围事项表达：

- 只存在于 Git 历史中的密钥、敏感文件或历史产物。
- 密钥轮换、令牌吊销、使凭据失效。
- 强制推送、清理历史、清理 Fork、清理缓存。
- 已发布包、容器镜像、CI 日志、registry 或部署环境中的历史副本清理。
- OS、网络协议、云基础设施、部署环境层面的治理。
- 全面密钥扫描、供应链扫描、依赖升级管理。

## 核心判断

Agent 可以修改的是本次运行提供的当前文件，并把这些修改固化为可审计的补丁。补丁能表达这些当前文件的变化，但不能表达已经发生过的历史传播是否被撤销。

Agent 不应该把以下操作当成自动修复能力：

- 重写 Git 历史，例如 `git rebase`、`git filter-repo`、`git filter-branch`。
- 删除、改写、重排既有 commit / tag / remote ref。
- 强制推送或任何需要仓库管理员协调的历史替换流程。
- 清理已经传播到 Fork、克隆副本、CI 日志、包 registry、容器镜像 registry、缓存、部署环境或第三方系统里的历史数据。

换句话说，Agent 的补丁可以改变“从现在开始仓库长什么样”，但不能保证“过去没有发生过”。历史已经泄露的密钥、历史 commit 中的大文件、旧产物中的敏感数据，通常需要人工治理和仓库管理员权限。

## 为什么不自动修 Git 历史

历史重写和普通代码修复有几处明显不同：

- **影响范围超出工作区**：本地工作区里的改动无法覆盖远程引用、Fork、克隆副本、缓存、registry、CI 日志等外部状态。
- **需要组织协调**：强制推送、密钥轮换、令牌吊销、清理 Fork、清理缓存通常需要权限、窗口期和人工确认。
- **容易破坏协作语义**：重写 commit 会影响 PR、branch、tag、release、下游克隆副本和审计记录。
- **修复证据不可由普通补丁表达**：一个 diff 可以证明当前文件不再含密钥，但不能证明所有历史副本都已清理。
- **容易诱导 Agent 空转**：在重整过的本地仓库或历史记录受限的工作区中，Agent 可能尝试大量 Git 命令，却无法完成真实治理。

因此，Git 历史清理应该被视为需要管理员执行的操作，而不是 Agent 自动补丁的一部分。

| 云、部署、操作系统或网络配置问题 | 只有仓库内配置直接决定时才进入候选；否则标为超出范围 | 不凭空修改外部环境                           | 不把缺少外部治理证明当作源码补丁失败               | 表达为人工或外部操作                                     |

## Agent 仍然可以做什么

如果一个历史问题在当前仓库里还有能补的地方，Agent 可以做这些防复发修复：

- 从当前文件删除仍存在的密钥、令牌、凭据或敏感样例。
- 增加 `.gitignore`、密钥扫描配置、提交前检查配置或生成规则。
- 修改代码或配置，避免继续生成、提交、打印或打包敏感数据。
- 在结果中明确提示需要密钥轮换、令牌吊销、清理历史、清理缓存、清理 Fork 等人工动作。
