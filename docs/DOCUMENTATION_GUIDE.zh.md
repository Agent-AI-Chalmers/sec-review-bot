# 文档指南

语言：[English](DOCUMENTATION_GUIDE.md) | 中文

本文是 [DOCUMENTATION_GUIDE.md](DOCUMENTATION_GUIDE.md) 的中文译文。英文版是权威版本；如果两者不一致，以英文版为准。

本指南定义仓库内维护文档的通用规则，适用于 package README、架构与 workflow 文档、契约指南和运维指南。生成产物与第三方材料遵循各自的源文件。

## 减少容易过时的表述

文档应说明系统当前如何工作，不必记录每次修改或重构的经过。读者使用、维护系统或理解已有数据需要历史背景时，再补充相关说明。

列表或服务名称已经写清楚时，通常不必再说一共有几个，以免内容更新后数量对不上。列举部分情况时，也不要把它写成完整清单。可以这样写：

- 用“支持的执行路径如下：”代替“有三种执行路径：”；
- 用具体服务名代替“这两个服务”；
- 列举示例时，用“例如”“包括”等措辞，不要写成“全部”或“仅有以下几种”。

不要因为数字以后可能变化就删掉它。读者配置、运行或理解系统需要的数值，以及代码或契约明确规定的数量限制，都应保留。例如，配置表中写着“超时时间默认为 60 秒”，就不能为了避免数字过时而改成“设有超时时间”；读者需要知道具体时长，才能判断是否调整配置。这里的 60 秒仅为示例，不是项目默认值。

## 标记可能变化的信息

有用的信息即使可能变化也应保留，并在所在段落、列表项或表格前添加 HTML 注释，注明来源以便日后核对。注释不会显示在 GitHub 渲染后的页面中，但可以在 Markdown 源文件中搜索到。

仓库所有的默认值和易变实现选择使用以下 marker：

```md
<!-- doc-default: <stable-key>; source=<repository-relative-path> -->
```

`<stable-key>` 填写对应的环境变量名、配置字段、导出常量名，或带包名的名称。`source` 填写实际定义该值的文件路径，相对于仓库根目录，不要填写另一篇说明文档的路径。例如，`AGENT_DOCKER_NETWORK_MODE` 的来源是 `agents/src/sec_review_agents/filesystem/docker_runtime.py`。

需要定期复核的外部事实或带日期判断使用以下 marker：

```md
<!-- doc-time-sensitive: <subject>; checked=<YYYY-MM-DD>; source=<URL-or-repository-relative-path> -->
```

`checked` 填写最近一次核对这条信息的日期。只有重新核对过来源，才能更新它；修改措辞或修正错别字时，不要顺手把日期改成当天。

来源内容变化时，也要核对并更新文档中的相关说明。中英文对应的标记内容必须一致。

使用以下命令查找已标记事实：

```bash
rg 'doc-(default|time-sensitive):' --glob '*.md' --glob '!docs/DOCUMENTATION_GUIDE*.md'
```

## 默认值与示例

默认值会影响读者如何操作或理解系统时，应保留在正文中。如果它只是参考数据，优先只在一处规范性配置表中维护。叙述需要解释该值的后果时可以重复，例如说明恢复可能暂停多久、并发限制如何影响调度；这类重复使用 `doc-default` 标记。

测量和实验结果应明确写成带日期的观察。不要把样本结果、当前依赖行为或外部发布计划写成永久系统属性。数字只作为示例参数且正文已经明确说明这一点时，不需要 marker。

## 文档审核

审核维护文档时：

1. 删除不增加含义的重复计数和穷举措辞。
2. 保留有运维价值的默认值、限制、日期和测量事实。
3. 添加或更新易变事实 marker，并核对其来源。
4. 检查绝对化表述是否有可强制执行的边界支撑。
5. 保持英文文档与译文的含义、标题和 marker 一致。
6. 运行 `AGENTS.md` 列出的文档检查。
