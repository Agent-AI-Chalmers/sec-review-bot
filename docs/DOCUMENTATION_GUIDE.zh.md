# 文档指南

语言：[English](DOCUMENTATION_GUIDE.md) | 中文

本文是 [DOCUMENTATION_GUIDE.md](DOCUMENTATION_GUIDE.md) 的中文译文。英文版是权威版本；如果两者不一致，以英文版为准。

本指南定义仓库内维护文档的通用规则，适用于 package README、架构与 workflow 文档、契约指南和运维指南。生成产物与第三方材料遵循各自的源文件。

## 优先使用耐久表述

直接描述当前系统。除非历史信息是操作系统或解释持久化数据所必需的，否则不要保留改写痕迹、迁移叙述或围绕旧版本组织的说法。

删除只是在重复统计附近内容、并且可能独立失效的细节。常见例子包括在列表前声明数量、统计同一句中已经点名的角色，以及把开放集合写成完整穷举。优先采用以下写法：

- 用“支持的执行路径如下：”代替“有三种执行路径：”；
- 使用所有者名称，而不是“两个服务”；
- 集合可能增长时使用“包括”，而不是“由……组成”；
- 成员已经点名后，使用“这些产物”“这些 worker”或“生命周期轴”。

不要仅仅因为数字可能变化就删除它。读者配置、运行或理解系统需要该值时，应当保留；数字表达受强制保障的不变量时也应保留，例如重试上限、超时、并发默认值、协议基数和单 maintainer 保证。

只有在行为受到代码、schema、运维边界或测试保障时，才使用“始终”“绝不”“只有”“恰好”和穷举列表。否则应把表述收窄到已有证据能够支持的范围。

## 易变事实

重要事实也可能随实现变化。只要它对读者有用，就应继续在正文中显示，并在包含该事实的段落、列表项或表格前紧邻放置 HTML comment。GitHub 不会渲染这些 comment，但源码搜索和文档审核工具可以找到它们。

仓库所有的默认值和易变实现选择使用以下 marker：

```md
<!-- doc-default: <stable-key>; source=<repository-relative-path> -->
```

`<stable-key>` 使用环境变量、配置字段、导出常量或带 package 限定的名称。`source` 必须指向拥有该值的仓库文件，不能指向另一篇说明文档。

需要定期复核的外部事实或带日期判断使用以下 marker：

```md
<!-- doc-time-sensitive: <subject>; checked=<YYYY-MM-DD>; source=<URL-or-repository-relative-path> -->
```

日期表示该说法最近一次经过核对的时间，而不是文档编辑时间。只有重新核对引用事实后才能更新日期。

Marker 表示复核义务，并不会自动保证正文正确。来源变化时，应更新所有依赖它的已标记表述。英文文档与译文必须使用相同的 marker key、source 和 checked date。

使用以下命令查找已标记事实：

```bash
rg 'doc-(default|time-sensitive):' --glob '*.md' --glob '!docs/DOCUMENTATION_GUIDE*.md'
```

排除本指南可以防止其中的 marker 模板进入真实复核义务集合。

## 默认值与示例

默认值会影响读者如何操作或理解系统时，应保留在正文中。如果它只是参考数据，优先只在一处规范性配置表中维护。叙述需要解释该值的后果时可以重复，例如说明恢复可能暂停多久、并发限制如何影响调度；这类重复使用 `doc-default` 标记。

测量和实验结果应明确写成带日期的观察。不要把样本结果、当前依赖行为或外部发布计划写成永久系统属性。数字只作为示例参数且正文已经明确说明这一点时，不需要 marker。

## 文档审核

审核维护文档时：

1. 删除不增加含义的重复计数和穷举措辞。
2. 保留有运维价值的默认值、限制、日期和测量事实。
3. 添加或更新易变事实 marker，并核对其来源。
4. 检查绝对化表述是否有可强制执行的边界支撑。
5. 保持英文文档与译文的含义、标题和 marker 一致。
6. 运行 `AGENTS.md` 列出的文档检查。
