# 记忆文件树产物 — v1

语言：[English](SPEC.md) | 中文

本文为 [SPEC.md](SPEC.md) 的中文译文；如有差异，以英文版为准。

## Envelope

v1 记忆文件树产物使用受限 POSIX PAX [envelope v1](../../../envelope/v1/SPEC.zh.md)。

| 属性                 | 必须值                                                                             |
| -------------------- | ---------------------------------------------------------------------------------- |
| 媒体类型             | `application/tar+zstd`                                                             |
| 摘要                 | 实际压缩归档字节的小写 `sha256`                                                    |
| 对象键               | `memory/trees/<hex>/memory-tree.v1.tar.zst`，其中 `<hex>` 是不带前缀的 64 字符摘要 |
| 最大压缩归档大小     | 64 MiB（`67,108,864` 字节）                                                        |
| 最大条目数量         | 10,000，包括文件和目录                                                             |
| 最大普通文件总大小   | 256 MiB（`268,435,456` 字节）                                                      |
| 最大单个普通文件大小 | 16 MiB（`16,777,216` 字节）                                                        |

单文件限制有意低于两个总量限制。记忆文件树中的 Markdown 文件受上述大小限制约束；单个文件不得耗尽压缩归档预算或主导解压内存。

消费者必须在解压前校验压缩字节大小和摘要，并在解析时执行条目数量与解压大小限制。在验证路径、类型、声明大小和元数据之前，不得提取条目。

通过对象存储引用产物时，读取方还必须检查 URI 是否精确指向由声明摘要计算出的对象键。仅匹配存储桶或目录前缀不够；引用 URI、摘要和实际压缩字节必须对应同一份产物。

## 必需目录树

归档只包含以下结构根：

<!-- autocorrect-disable -->

```text
manifest.json
memory/
memory/MEMORY.md
memory/topics/
memory/topics/**/*.md  （可选）
```

<!-- autocorrect-enable -->

`manifest.json` 是 UTF-8 JSON 文件，其字节必须精确为：

```json
{"version":1}
```

并以一个 LF 字节结尾。解析值必须符合 [manifest.schema.json](manifest.schema.json)：对象只包含值为 `1` 的整数 `version` 字段。

`memory/MEMORY.md` 与 `memory/topics/` 下的所有普通文件必须是合法 UTF-8 Markdown。主题文件必须以 `.md` 结尾。`memory/topics/` 下允许使用目录分组，但禁止空路径片段、`.`、`..`、绝对路径、反斜杠、NUL 字节与重复路径。路径使用 `/`，相对归档根，并采用规范形式：普通文件路径不以斜杠结尾，目录路径恰好以一个斜杠结尾。

不允许其他路径。尤其是 `memory/` 下除 `MEMORY.md` 外的文件，以及 `memory/topics/` 下非 Markdown 文件，均无效。

## 条目编码

条目类型和元数据必须符合 envelope 要求。读取方直接检查 tar 头部的类型，不得跟随链接。

路径无法放入 ustar `name` 与 `prefix` 字段时，允许使用 envelope 的局部 PAX `path` 扩展头。其他 PAX 与 GNU 扩展仍然无效。

## 顺序

`manifest.json` 必须是第一个条目。其余条目按规范路径的字节字典序升序排列。必需父目录必须作为条目存在；除字典序规则外，不额外要求父目录先于子项。

归档至少以两个全零的 512 字节块结束。tar 结束标记后的字节只能是全零填充。

## 规范生产

生产者必须输出规定的条目集合、元数据、顺序与 JSON 字节；只有有效路径无法放入 ustar 字段时才使用局部 PAX `path` 扩展头；随后将 tar 数据流压缩为一个 Zstandard 帧。契约不固定压缩器实现或压缩级别：产物标识是实际压缩字节的 SHA-256 摘要，对象键由该摘要派生。

消费者可接受任何符合标准且解压后 tar 满足本规范的 Zstandard 帧。解码器能够识别多个帧拼接或帧后附带非帧数据时，必须拒绝这些输入。

生成方必须确保所用归档库的输出符合共享的受限 PAX 格式。读取方则检查实际存储的数据，包括高层归档 API 在返回条目时可能隐藏的扩展头；不能因为库能读出文件，就跳过这些检查。

## 共享测试输入

[corpus/manifest.json](corpus/manifest.json) 记录每个已提交 `.tar.zst` 用例的用途、逻辑条目数量、压缩字节 SHA-256 摘要、精确压缩大小与预期结果。普通用例包含按顺序列出的实际条目；大型压力用例可以省略重复列表，同时保留真实归档与聚合数量。测试输入包含合法的最小目录树、主题文件、字节排序和长路径 PAX 目录树，以及覆盖错误字节序、缺失索引、错误清单、路径穿越、符号链接、意外路径、意外条目类型、不支持的 PAX 元数据和条目数量上限的非法归档。

测试归档由 `tools/src/generate.ts` 生成。契约测试校验真实压缩字节和归档语义；文件名或清单标签本身不能作为判定依据。
