# Scanner Finding Triage Source Notes

These sources support scanner-specific rules about observation coverage, component and version inference, SCA presence versus use, target mismatch and severity metadata.

| Rule group and reference | Primary source and locator | Supported decision and limit |
| --- | --- | --- |
| TRIAGE-1: scanner output is a lead; `reachability-and-context.md` | [Rapid7 false-positive investigations](https://docs.rapid7.com/insightvm/false-positive-investigations), investigation causes and verification steps | Scanner configuration, credentials, templates, and coverage can make a result inaccurate. This supports independent verification; it does not establish that any particular finding is false. |
| TRIAGE-2: package or function presence versus use; `reachability-and-context.md` | [Chainguard scanner false results](https://edu.chainguard.dev/chainguard/chainguard-images/staying-secure/working-with-scanners/false-results/), package and vulnerable-function examples | Presence is weaker than reachable execution. Absence of demonstrated use is still a proof gap unless repository evidence establishes that the relevant code is unused or unreachable. |
| TRIAGE-3: scanner target and path mismatch; `scanner-noise-patterns.md` | [DevGuard false-positive detection](https://docs.devguard.org/explanations/vulnerability-management/false-positive-detection/), path-based false-positive handling | A scanner-specific rejection should identify the component, target or path assumption that does not apply. A blanket false-positive label is insufficient. |
| TRIAGE-4: contextual prioritization; `scanner-noise-patterns.md` | [CISA SSVC](https://www.cisa.gov/stakeholder-specific-vulnerability-categorization-ssvc), exploitation and technical-impact decision points | Context affects prioritization, but the full SSVC workflow and vocabulary are not required for repository triage. |
| TRIAGE-5: severity is separate from validity; `scanner-noise-patterns.md` | [FIRST CVSS specification](https://www.first.org/cvss/specification-document), scoring model and metrics | A severity score does not prove reachability or vulnerability validity. Repository triage should not infer confirmation from a scanner-provided score. |
