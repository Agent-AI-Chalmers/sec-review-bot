# Software Supply Chain Security Source Notes

Reviewed 2026-10-16. The bundled skill is limited to dependency candidate selection and code executed during install/build. CI artifact promotion remains in `ci-security`; dependency-CVE reachability remains in `scanner-finding-triage`; cryptographic verification remains in `cryptography-security`.

| ID and skill location | Primary source and locator | Supported decision and limit |
| --- | --- | --- |
| SUPPLY-1: pip candidate sources; `dependency-selection.md` | [pip install](https://pip.pypa.io/en/stable/cli/pip_install/), “Finding Packages” and the `--extra-index-url` warning | A public candidate can substitute for an intended private package when the actual pip configuration permits it. Do not generalize pip selection to other ecosystems or report multiple indexes without an attacker-publishable candidate. |
| SUPPLY-2: lock enforcement; `dependency-selection.md` | [pip Secure Installs](https://pip.pypa.io/en/stable/topics/secure-installs/), hash checking and pinned dependencies; [npm package-lock.json](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/) | Determine whether the actual command consumes the reviewed lock/hash data. Lockfile presence alone does not establish source identity or execution behavior. |
| SUPPLY-3: npm lifecycle execution; `install-build-execution.md` | [npm scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts/), lifecycle scripts and operation order | Dependency code can execute during install/build before runtime import. Verify package source, selected version, command and enabled scripts. |
| SUPPLY-4: disabling scripts; `install-build-execution.md` | [npm config `ignore-scripts`](https://docs.npmjs.com/cli/v11/using-npm/config#ignore-scripts) | `ignore-scripts` changes lifecycle execution within its documented scope; it does not establish package identity or safety in other tools. |
| SUPPLY-5: provenance boundary | [SLSA v1.2 Threats Overview](https://slsa.dev/spec/v1.2/threats-overview) | Provenance and promotion are not in the first bundled references. Presence of an attestation is not proof that the consumer verifies the intended identity/policy; CI owns artifact production/promotion authority. |
| SUPPLY-6: Cargo sources and build scripts; `cargo-dependencies.md` | [Cargo Source Replacement](https://doc.rust-lang.org/cargo/reference/source-replacement.html); [Cargo Build Scripts](https://doc.rust-lang.org/cargo/reference/build-scripts.html) | Source replacement has Cargo-specific identity assumptions, while `build.rs` executes during the build. Require an attacker-selectable crate or script and concrete build authority. |
| SUPPLY-7: JVM dependency and plugin resolution; `jvm-build-dependencies.md` | [Maven Repositories](https://maven.apache.org/guides/introduction/introduction-to-repositories.html); [Gradle Declaring Repositories](https://docs.gradle.org/current/userguide/declaring_repositories_basics.html); [Gradle Initialization Scripts](https://docs.gradle.org/current/userguide/init_scripts.html) | Dependency, plugin and initialization sources can differ. Verify the repository's wrapper/tool version, content filters and selected coordinates rather than encoding current defaults. |
| SUPPLY-8: Go module sources and checksums; `go-modules.md` | [Go Modules Reference](https://go.dev/ref/mod), environment variables for proxies, private modules and authenticating modules | `GOPROXY`, private-module settings, replacements and checksum controls jointly determine selection and authentication. A private path disclosure is not automatically code substitution. |
| SUPPLY-9: provenance consumption; `provenance-verification.md` | [SLSA v1.2 Verifying Artifacts](https://slsa.dev/spec/v1.2/verifying-artifacts); [in-toto Attestation Framework](https://github.com/in-toto/attestation/blob/main/spec/README.md) | A consumer must bind the admitted artifact to the attested subject and policy. Attestation presence or signature validity alone is insufficient; missing provenance alone is not a finding. |
| SUPPLY-10: update trust and freshness; `tool-plugin-updates.md` | [The Update Framework Specification](https://theupdateframework.github.io/specification/latest/), roles and rollback/freeze attacks | A checksum from the same compromised channel is not an independent trust root. Freshness requirements depend on the update contract; do not turn every absent updater feature into a finding. |
